---
title: /hotfix
description: Turn an urgent bug report into a concise item and start delivery.
---

`/hotfix` creates a short work item as soon as the destination and essential
report information are available. It sends the saved ID to `/pick`, which
presents the item and requests plan approval before delivery.

## How `/hotfix` starts delivery

## What `/hotfix` does

<table class="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Resolve</th>
      <td>Find the destination in the configured Linear or ClickUp provider.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Draft</th>
      <td>Describe the symptom, impact, expected result, and verification when known. Ask one focused question only if the failure or intended correction is unclear. Do not inspect code to fill gaps.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Save</th>
      <td>Create the item once the destination and essential report information are available, and require <code>agent-shaped</code> before continuing. Report a failed <code>hotfix</code> label without blocking delivery.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Continue</th>
      <td>Pass the saved item ID to <code>/pick</code>, which checks eligibility, presents the item once, and requests plan approval before <code>/work → /ready → /inspect</code>.</td>
    </tr>
  </tbody>
</table>
