`/work` executes an approved plan autonomously, one todo at a time. It routes
each todo to the right specialist and hands the completed plan directly to
`/ready` without another approval.

## Skills used under the hood

`/work` selects the most suitable specialist for the active todo. That
specialist loads only the skills whose triggers apply and may work directly
when none are needed.

## What `/work` does

<table className="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Initialize</th>
      <td>For new work, start from a clean default branch, create and push one work branch, open one draft request, and link it to the item.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Route</th>
      <td>Select or reuse the most suitable specialist for the active todo and load only the skills its activity triggers.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Execute</th>
      <td>Persist the todo as in progress, implement and validate only its scope, then stage only its changes.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Commit</th>
      <td>Commit the result, persist todo completion immediately, and continue without pushing.</td>
    </tr>
    <tr>
      <td>5</td>
      <th scope="row">Ready</th>
      <td>When every todo is complete, continue automatically to <code>/ready</code>; later findings return through the same loop as corrective todos.</td>
    </tr>
  </tbody>
</table>
