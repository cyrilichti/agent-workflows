---
title: /work
description: Execute one selected plan todo by todo on a draft merge request.
---

`/work` turns an approved plan into confirmed commits. It can receive the plan
from `/pick` with an active official item, or let you select from the 10 most
recently modified `.plan.md` files.

## How this workflow is structured

<table className="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Plan</th>
      <td>Use the supplied plan or select one in standalone mode.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Branch</th>
      <td>Initialize new work or trust the current branch when resuming.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Request</th>
      <td>Create the GitLab draft merge request for new work.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Todo</th>
      <td>Select a specialist and execute one todo.</td>
    </tr>
    <tr>
      <td>5</td>
      <th scope="row">Commit proposal</th>
      <td>Confirm the proposed commit or request an adjustment.</td>
    </tr>
    <tr>
      <td>6</td>
      <th scope="row">Commit</th>
      <td>Create the confirmed commit and complete the todo.</td>
    </tr>
    <tr>
      <td>7</td>
      <th scope="row">Validation</th>
      <td>Run the plan's global validation and stop.</td>
    </tr>
  </tbody>
</table>
