`/write` turns a rough need or an existing item into one confirmed,
provider-backed ticket. It asks only for missing context, routes qualification
to the best-fit writing skill when needed, and never saves without human
approval.

## What `/write` does

<table class="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Resolve</th>
      <td>Infer create or update, resolve the configured provider, then find the destination or existing item.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Qualify</th>
      <td>Ask only for decisions that are still missing. Use at most one best-fit writing skill when it helps.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Understand</th>
      <td>For qualified needs, require human confirmation of the concise understanding before drafting.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Draft</th>
      <td>Present one complete item, revise it when requested, and wait for an explicit <code>Save item</code> decision.</td>
    </tr>
    <tr>
      <td>5</td>
      <th scope="row">Save</th>
      <td>Create or update the item, apply <code>agent-shaped</code>, and report the provider result.</td>
    </tr>
  </tbody>
</table>
