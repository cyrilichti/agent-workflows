---
title: /project
description: Resolve a ticket destination to one local project directory.
---

`/project` finds the local Git repository for a destination name (`list`) and
an exact item ID. Invoke it as `/project` or `$project` with both values, or let
the Kestra `work` flow call it after `/next` returns an item. It reads the item
only when several repositories match the destination.

## What `/project` does

<table class="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Require</th>
      <td>Reject a missing or blank <code>list</code> or exact item ID before searching.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Search</th>
      <td>Match Git repository roots from Codex's configured projects first, then repositories beside them, then under <code>~</code>. Exact names outrank names with a separator-boundary suffix: <code>aftersales</code> matches <code>aftersales-api</code>, but not <code>aftersalesman</code>. Matching ignores case, spaces, hyphens, and points. The home search does not follow symlinks or enter <code>.git</code>, <code>node_modules</code>, or a repository already found.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Choose</th>
      <td>For several matches, read the complete item. Prefer a uniquely named repository, then its clear primary target, then a frontend repository over an incidental API or backend match, and finally the alphabetically first absolute path.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Return</th>
      <td>Return <code>{'{"path":"/absolute/repository/path"}'}</code>, or <code>{'{"status":"not found"}'}</code> after a complete search, or <code>{'{"status":"search incomplete"}'}</code> when the home search cannot finish without an exact match. Input and execution failures are errors, not resolution results.</td>
    </tr>
  </tbody>
</table>
