---
title: /project
description: Resolve a ticket destination to one local project directory.
---

`/project` finds the local Git repository for a destination name (`list`) and
an exact item ID. Invoke it as `/project` or `$project` with both values, or let
the Kestra `work` flow call it after `/next` returns an item. It reads the item
only when several repositories match the destination. Configured project paths
take priority when available; each selected search tier is completed so
competing exact matches can be resolved independently of discovery order.

## What `/project` does

<table class="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Require</th>
      <td>Reject a missing or blank <code>list</code> or exact item ID before searching.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Search</th>
      <td>Search configured project directories first, then neighboring repositories and the home directory if needed. Complete the first matching tier, retain all exact matches when present, and otherwise retain prefix matches.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Choose</th>
      <td>For several matches, use the complete item to identify the primary repository, then apply stable tie breaks.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Return</th>
      <td>Return one absolute path, <code>not found</code>, or <code>search incomplete</code>. Invalid input or a failed search is an error.</td>
    </tr>
  </tbody>
</table>
