---
title: /project
description: Resolve a ticket destination to one local project directory.
---

`/project` finds the local Git repository for a destination name (`list`) and
an exact item ID. Invoke it as `/project` or `$project` with both values, or let
the Kestra `work` flow call it after `/next` returns an item. It reads the item
only when several repositories match the destination. The active AI provider
must expose its configured project paths to the workflow.

## What `/project` does

<table class="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Require</th>
      <td>Reject a missing or blank <code>list</code> or exact item ID before searching.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Search</th>
      <td>Search configured project directories first, then neighboring repositories and the home directory if needed. Match Git repository roots by name, preferring exact matches and ignoring case and separators.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Choose</th>
      <td>For several matches, use the complete item to identify the primary repository, then apply stable tie breaks.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Return</th>
      <td>Return one absolute path, <code>not found</code>, or <code>search incomplete</code>. Invalid input or unavailable configuration is an error.</td>
    </tr>
  </tbody>
</table>
