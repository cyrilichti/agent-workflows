---
title: /plan
description: Create and approve one implementation plan without starting work.
---

`/plan` creates and approves one implementation plan without starting
implementation or changing provider state. It can run standalone from the
current request, deriving one transient item only when context is missing, or
inside another workflow from the official item supplied by the caller.

Before drafting, it checks that the context represents one coherent delivery
unit. Otherwise, it returns `needs-refinement` and stops without creating a
plan.

## How this workflow is structured

<table class="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Context</th>
      <td>Use the caller's item or resolve standalone context.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Scope</th>
      <td>Confirm the work is one coherent delivery unit.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Specialist</th>
      <td>Select one plan author and inspect the local technical context.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Draft</th>
      <td>Route planning skills and write one implementation plan.</td>
    </tr>
    <tr>
      <td>5</td>
      <th scope="row">Confirm</th>
      <td>Review, adjust, and approve the plan.</td>
    </tr>
    <tr>
      <td>6</td>
      <th scope="row">Return</th>
      <td>Return the approved plan to the caller or stop standalone.</td>
    </tr>
  </tbody>
</table>
