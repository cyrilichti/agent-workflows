---
title: /inspect
description: Inspect and publish one exact request snapshot autonomously.
---

`/inspect` receives the delivery context from `/ready`, or in standalone mode
asks for the local plan, item, and exact request. It freezes one snapshot,
publishes every valid finding without manual curation, and observes the result.

Blocking findings return to `/work` as corrective todos. When none is blocking,
`/inspect` applies `agent-inspected` and stops. It never invokes `/done`.

## How this workflow is structured

<table className="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Context</th>
      <td>Use caller context or select the local plan, official item, and exact request.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Snapshot</th>
      <td>Freeze the complete open, non-draft request state and head SHA.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Inspect</th>
      <td>Produce a complete SHA-bound result with persistent finding IDs.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Publish</th>
      <td>Publish unseen findings once for the unchanged SHA and observe the result.</td>
    </tr>
    <tr>
      <td>5</td>
      <th scope="row">Continue</th>
      <td>Return blocking findings to <code>/work</code>, or apply <code>agent-inspected</code> and stop.</td>
    </tr>
  </tbody>
</table>
