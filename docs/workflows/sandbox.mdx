`/sandbox` accepts a work item's ID, native URL, title, or search phrase and
prepares an isolated environment in the current project, returning a reusable JSON context.
Pass that context back to `/sandbox` to remove its resources. The workflow ends
after returning its result; delivery callers decide when to use the environment.

## What `/sandbox` does

<table className="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Select</th>
      <td>A supplied <code>sandbox_context</code> selects teardown. For preparation, supply <code>item</code> as an ID, native URL, title, or search phrase. Resolve the official item, asking for clarification when needed, then read its approved plan from the item comments.</td>
    </tr>
    <tr>
      <td>2a</td>
      <th scope="row">Read the plan</th>
      <td>Preparation reads the approved plan in the item's comments. If it requires project code or services to run in a container and the project has a Compose configuration, include container execution. Otherwise, create a worktree without it.</td>
    </tr>
    <tr>
      <td>3a</td>
      <th scope="row">Resolve dependencies</th>
      <td>Only for container execution, the agent identifies local repositories named in the README and resolves new names together with a local-only command. It reads each newly found repository's README once and supplies the distinct absolute paths. Preparation validates those paths before allocation.</td>
    </tr>
    <tr>
      <td>4a</td>
      <th scope="row">Create</th>
      <td>Create a detached worktree at each selected repository's current <code>HEAD</code> and copy Git-ignored resources with their paths and permissions. When container execution is available, start the Compose services of the project and its dependencies in one sbx shell sandbox, then allocate ports. Return the resulting <code>sandbox_context</code>; on failure, attempt rollback and report the stage and reason.</td>
    </tr>
    <tr>
      <td>2b</td>
      <th scope="row">Tear down</th>
      <td>Verify context ownership, then remove its optional Docker sandbox and recorded worktrees. Accept partial preparation records and repeated teardown, preserve the main checkouts, and return the result.</td>
    </tr>
  </tbody>
</table>
