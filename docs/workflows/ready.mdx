`/ready` prepares a completed implementation for review. It checks the recorded
plan and branch state, promotes the linked request, and continues to
`/inspect`.

## How `/ready` promotes completed work

`/ready` checks that the plan records completed validation; it does not run
those checks or inspect the implementation. A failed check stops the workflow
with its stage and reason.

## What `/ready` does

<table className="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Verify</th>
      <td>Require at least one completed todo, no pending or in-progress todos, checked validation, and one clean branch that is not behind or diverged.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Resolve</th>
      <td>Require the current branch and exact linked request to match the delivery context.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Push</th>
      <td>Push only when the local branch is ahead of its upstream.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Promote</th>
      <td>Use the complete plan as the request description and mark the request ready.</td>
    </tr>
    <tr>
      <td>5</td>
      <th scope="row">Inspect</th>
      <td>After observing every required request update, continue automatically to <code>/inspect</code>.</td>
    </tr>
  </tbody>
</table>

## Execution details

A delivery context can come directly from `/work`. In standalone mode,
`/ready` resolves it from one item ID, URL, title, or search phrase.
