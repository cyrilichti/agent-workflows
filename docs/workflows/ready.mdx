---
title: /ready
description: Validate completed work, promote it, and continue to inspection autonomously.
---

`/ready` receives a delivery context from `/work`, or in standalone mode asks
for the plan and item before resolving the exact request. Gaps return to
`/work`; passing work is promoted and handed to `/inspect` automatically.

## How this workflow is structured

<table className="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Context</th>
      <td>Use caller context or select a local plan, item, and exact request.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Verify</th>
      <td>Require terminal work and one clean, non-behind branch snapshot.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Match</th>
      <td>Run only planned validation, then compare the complete branch diff with the Objective and Expected Outcome.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Plan comment</th>
      <td>Create or update the request's single complete plan comment.</td>
    </tr>
    <tr>
      <td>5</td>
      <th scope="row">Promote</th>
      <td>Push if needed, update and mark the request ready, transition the item when possible, then invoke <code>/inspect</code>.</td>
    </tr>
  </tbody>
</table>
