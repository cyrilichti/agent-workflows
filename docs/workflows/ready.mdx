---
title: /ready
description: Validate completed work, promote it, and continue to inspection autonomously.
---

`/ready` receives a delivery context from `/work`, or in standalone mode asks
for the plan, item, and exact request. It verifies the complete delivery
against the approved plan, returns concrete gaps to `/work`, and promotes
passing work for inspection.

`/ready` runs only the validation defined by the plan. It checks delivery
completeness, but does not select a specialist or perform an independent code
review.

## What `/ready` does

<table className="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Verify</th>
      <td>Require a terminal plan, completed work, and one clean branch that is not behind or diverged.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Match</th>
      <td>Run only planned validation and compare the complete branch diff with the Objective and Expected Outcome.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Repair</th>
      <td>Return each concrete gap to <code>/work</code> as a corrective todo, then verify the corrected delivery again.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Promote</th>
      <td>Push when needed, use the complete plan as the request description, mark the request ready, and move the item to review when possible.</td>
    </tr>
    <tr>
      <td>5</td>
      <th scope="row">Inspect</th>
      <td>After observing every required request update, continue automatically to <code>/inspect</code>.</td>
    </tr>
  </tbody>
</table>
