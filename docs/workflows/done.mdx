---
title: /done
description: Squash-merge one exact request, then complete its official item.
---

`/done` accepts either a compact caller packet from `/inspect` or standalone
item and request resolution. Both paths join the same preflight.

An open request must be non-draft, mergeable at the unchanged head SHA, and
support squash merge. The item moves to its resolved completed state only after
the request is observed as merged.

## Flow

<table className="workflow-steps">
  <tbody>
    <tr>
      <td>1</td>
      <th scope="row">Context</th>
      <td>Reuse the caller packet or resolve one review item and its exact request.</td>
    </tr>
    <tr>
      <td>2</td>
      <th scope="row">Preflight</th>
      <td>Resolve the item target and verify merge eligibility and squash support.</td>
    </tr>
    <tr>
      <td>3</td>
      <th scope="row">Confirm</th>
      <td>Confirm the exact remaining mutations once.</td>
    </tr>
    <tr>
      <td>4</td>
      <th scope="row">Complete</th>
      <td>Recheck, squash-merge, transition the item, and report observed results.</td>
    </tr>
  </tbody>
</table>

A stale standalone confirmation returns to preflight. A changed caller SHA
returns to `/inspect` for a new approval. A failed item transition never retries
or rolls back an observed merge; a rerun offers only that transition.
