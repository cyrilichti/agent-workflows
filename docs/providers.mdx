---
title: Providers
description: Connect item and version operations to their configured providers.
---

Agent Workflows separates where work is managed from where code is delivered.
Configure one provider for each responsibility; workflows route every operation
to the integration selected by the project.

## Work items: ClickUp or Linear

The item provider owns ticket lookup, creation, comments, labels, and status
changes. Approved plans are published and read through the same provider
boundary.

```yaml
mcp:
  item:
    provider: linear # or clickup
```

## Code delivery: GitHub or GitLab

The version provider owns branches, commits, pull or merge requests, and reviews.

```yaml
mcp:
  version:
    provider: github # or gitlab
```

The `mcp.version.provider` key is retained for existing project configurations;
`github` selects the `gh` CLI.

## Configure provider access

ClickUp operations use the community
[`clickup-cli`](https://github.com/nicholasbester/clickup-cli) directly.
Install it and configure its API token and Workspace in the environment running
the agent. Follow the upstream [installation and authentication guide](https://clickup-cli.com/install/)
and [command reference](https://clickup-cli.com/commands/).

Linear operations use the community
[`schpet/linear-cli`](https://github.com/schpet/linear-cli) directly. Install it
on the machine running the agent and authenticate with a Linear API key:

```bash
brew install schpet/tap/linear
linear auth login
```

The CLI must be available as `linear` on `PATH`. See the upstream
[installation and setup guide](https://github.com/schpet/linear-cli#install) for
other installation methods and workspace configuration. The provider contracts
use native CLI commands and `linear api` for focused GraphQL queries. The
`mcp.item.provider` key is retained for existing project configurations;
`clickup` and `linear` select their respective CLIs.

GitHub operations use the official [`gh` CLI](https://cli.github.com/).
Install it and authenticate it for the repository's host before selecting
GitHub:

```bash
gh auth login --hostname github.example.com
```

For GitHub.com, use `gh auth login`. See the
[`gh` installation guide](https://github.com/cli/cli#installation) and
[authentication guide](https://cli.github.com/manual/gh_auth_login).

GitLab operations use the official `glab` CLI instead of an MCP server. Install
[`glab`](https://docs.gitlab.com/cli/installation/), then authenticate it for
the repository's host before selecting GitLab:

```bash
glab auth login --hostname gitlab.example.com
```

For GitLab.com, run `glab auth login`. See GitLab's
[authentication guide](https://docs.gitlab.com/cli/authentication/) for OAuth,
personal access token, CI, and self-managed instance options.
