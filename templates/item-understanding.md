# Item Understanding

Use after qualification converges and before drafting a complete item.

## Format (Markdown)

```markdown
**Understanding**

- **Outcome:** <result actually sought>
- **User and reason:** <beneficiary and problem, when relevant>
- **Success:** <how the result will be recognized>
- **Constraints and risks:** <material constraints, risks, or assumptions, when relevant>
<when a relevant exclusion is established: - **Out of scope:** <explicit non-goals>>
```

## Rules

- Keep `Outcome` and `Success`; omit other irrelevant lines.
- Include `Out of scope` only when a relevant exclusion is established.
- When an exclusion is needed to resolve a scope ambiguity but is not
  established, ask for clarification before presenting the summary. Never
  invent an exclusion.
- Use one bold inline lead-in rather than a section heading.
- State unresolved material questions instead of inventing answers.
- Do not include an item title, item body, provider metadata, implementation
  plan, or save choice.
