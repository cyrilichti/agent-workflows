# Item Understanding

Use after qualification converges and before drafting a complete item.

## Format (Markdown)

```markdown
## Understanding

- **Outcome:** <result actually sought>
- **User:** <beneficiary or affected audience, when relevant>
- **Why:** <problem or reason, when relevant>
- **Success:** <how the result will be recognized>
- **Constraints:** <binding constraints, when relevant>
- **Risks and assumptions:** <material risks or assumptions, when relevant>
- **Out of scope:** <explicit non-goals>
```

## Rules

- Keep the summary concise and use only lines relevant to the item, except
  `Outcome`, `Success`, and `Out of scope`, which are required.
- State unresolved material questions instead of inventing answers.
- Do not include an item title, item body, provider metadata, implementation
  plan, or save choice.
- The summary is working understanding for explicit confirmation, not a draft
  item and not persisted provider content.
